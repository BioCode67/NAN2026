# 상장폐지 대난투 (Delisting Brawl)

CEO와 밈 캐릭터들이 **주가를 걸고** 싸우는 2D SD 대난투 게임.
체력이 곧 주가다. 때릴수록 내 주가가 오르고, **0%가 되면 상장폐지**된다.

**캐릭터 20명 · 무대 4곳 · 기술 280개.** 한 판은 1P 대 3AI,
이기면 그 자리에서 **다음 상대**가 나온다 (연승 도전).

### 연속기

**같은 버튼을 이어 누르면 다음 타로 넘어간다.** 한 대씩 툭툭 치는 대신
몰아치라는 뜻이고, 이 게임 전투의 기본 리듬이다.

| 커맨드 | 흐름 |
|---|---|
| `J` `J` `J` | 1타 → 2타 → **마무리(크게 띄운다)** |
| `K` `K` | 1타 → **마무리(멀리 날린다)** |

- **후딜을 건너뛴다.** 판정이 끝나는 순간 다음 타로 넘어가므로 끊기지 않는다
- **선입력을 받는다.** 모션이 끝나기 전에 눌러도 기억했다가 이어친다 —
  빠르게 누를수록 잘 나간다
- **끝나고도 잠깐은 이어진다.** 후딜이 풀린 뒤 0.26초까지 유효하다
- **맞으면 끊긴다.** 이어치기가 공짜가 되지 않게 하는 대가
- **마무리 타는 방어를 깬다.** 가드로 버티기만 하면 기절해 무방비가 된다
- 방향키(`W`/`S`)를 섞으면 연속기 대신 그 방향 기술이 나간다 — 흐름을 끊고
  다른 선택지로 빠지는 셈

마무리 타는 히트스탑이 1.5배로 늘고, 화면 섬광·충격선·카메라 밀림이 함께 붙는다.
연타가 쌓일수록 한 대가 무거워지고(최대 +60%) 타격음 피치도 올라간다.

지상에서 `J J J`로 띄우고 → 점프해서 공중 `J`/`K`로 이어붙인 뒤 →
공중 `S`+`K` 급강하로 처박는 것이 기본 콤보 루트다.

### 커맨드 무브

버튼 세 개로 기술 세 개만 쓰는 게임이 되지 않도록, **방향을 섞으면 다른 기술이 나간다.**
캐릭터마다 열네 개의 기술이 있고, 이름·모션·판정 위치가 전부 다르다.

| 커맨드 | 역할 |
|---|---|
| `J` / `K` | 기본 약·강공격 (연속기 시작) |
| `W`+`J` | 상단 견제 — 위로 쳐올려 콤보를 시작한다 |
| `W`+`K` | 상승 강타 — **자신도 함께 솟구치며** 크게 띄운다 |
| `S`+`J` | 하단 견제 — 리치가 길지만 띄우지 못한다 |
| `S`+`K` | 내려찍기 — 좌우 양쪽을 함께 치는 광역기 |
| 공중 `J` / `K` | 공중 견제 / 몸을 돌려 주변을 훑는 회전 공격 |
| 대시 중 `J`/`K` | 돌진 공격 — 거리를 좁히면서 그대로 부딪친다 |
| 공중 `S`+`J`·`K` | 급강하 찍기 — 상대를 **아래로 처박는다**. 장외 마무리기 |
| `L` | 시그니처 스킬 (쿨다운) |

기술 이름은 그 인물에서 나온다. 같은 `S`+`K`라도
빌 게이츠맨은 **반독점 소송**, 일론 머스크맨은 **착륙 실패**,
패니 와이즈맨은 **하수구 개봉**이다. 전체 목록은 캐릭터 선택 화면에서 볼 수 있다.

## 캐릭터 고유 메커니즘 — 스무 명이 다섯 갈래로 갈린다

패시브(주가 흡수율 등)는 숫자만 다를 뿐 **조작이 같다.** 그것만으로는
"이름만 다른 같은 캐릭터"가 된다. 그래서 **버튼을 누르는 방식 자체가 다른 규칙**을
다섯 갈래로 만들고, 스무 명이 넷씩 나눠 쓴다. 한 명을 파고들 이유가 여기 있다.

| 캐릭터 | 고유 규칙 | 어떻게 다루나 |
|---|---|---|
| 📈 **빌 게이츠맨** — 지분 확보 | 타격마다 지분 +1 (최대 5). 스킬이 쌓인 지분을 전부 태운다 | **참았다 터뜨리는 캐릭터.** 5지분 블루스크린은 판을 멈춰 세운다 |
| 💡 **스티브 잡스맨** — 원 모어 씽 | 스킬이 **적중하면** 1.6초 안에 `L`을 한 번 더 눌러 쿨다운 없이 재시전 | 맞히는 순간이 곧 다음 기회다. 스킬 두 방이 이어진다 |
| 🔥 **일론 머스크맨** — 부스터 | 대시가 부스터를 1칸 쓴다 (최대 3, 자동 충전) | **이 게임에서 유일하게 공중 대시를 쓴다.** 장외 복귀·이탈 수단 |
| 🍴 **리누스 토발즈맨** — 포크 | 방어로 막아낸 기술을 훔쳐 저장. 다음 `L`이 그 기술로 나간다 | **막는 것이 곧 습득.** 상대의 강한 기술을 일부러 받아내 되돌려준다 |
| 🎈 **패니 와이즈맨** — 붉은 풍선 | 타격마다 풍선 +1 (최대 3). 풍선 하나당 공중 점프가 한 번 늘어난다 | 때려서 기동력을 번다. 대신 **한 대라도 맞으면 전부 터진다** |

자원은 HUD 패널에 `◆◆◇◇◇` 로 표시된다. 몇 개 쌓였는지 보이지 않으면
"그때그때 다르게 동작하는 캐릭터"로만 느껴지기 때문이다.

**상대 셋은 서로 다른 메커니즘으로 뽑는다.** 무작위로만 두면 봇 셋이 같은
방식으로 싸우는 판이 생기고, 그러면 로스터를 스무 명으로 늘린 이유가 사라진다.
얼굴은 매 판 달라지고, 싸우는 방식만 항상 셋으로 갈린다.

## 프롬프트 오브 — AI로 판을 바꾼다

이 게임의 핵심 기믹. 스매시브라더스의 스매시볼 자리에 **프롬프트 오브**가 있다.

```
떠다니는 오브를 때려 깬다  →  깬 사람이 문장을 입력한다  →  판이 통째로 바뀐다
```

- 오브는 전투 중 주기적으로 나타나 8자를 그리며 떠다닌다
- 체력이 있어 한 대로는 안 깨진다 — **누가 마지막 타를 넣느냐**의 싸움이다
- 근접기·투사체 모두 통한다. 방치하면 달아난다
- 깬 사람이 플레이어면 입력창이 뜨고 판이 멈춘다. **AI가 깨면 봇이 대신 외친다**

입력한 문장은 세 갈래 중 하나로 해석된다.

| 갈래 | 예시 입력 | 결과 |
|---|---|---|
| **아이템** | `폭탄을 뿌려라` | 건드리면 터지는 폭탄이 떨어진다 |
| | `아이템을 쏟아부어` | 아이템 여섯 개가 한꺼번에 쏟아진다 |
| | `회복 좀 시켜줘` / `무기를 달라` | 회복·공격 강화 아이템만 무더기로 |
| **맵** | `여기를 달로 만들어줘` | 중력이 절반. 모두가 붕붕 뜬다 |
| | `바람이 불게 해줘` | 강풍이 한쪽으로 계속 밀어낸다 |
| | `용암 지대로` | 지면이 불탄다. 바닥에 서 있으면 주가가 녹는다 |
| | `발판을 다 부숴` | 공중 발판이 전부 무너진다 |
| | `불을 꺼버려` | 정전. 자기 주변밖에 안 보인다 |
| **룰** | `리듬으로 승부하자` | **리듬 배틀** — 박자에 맞춰 때리면 2배, 어긋나면 절반 |
| | `한 방이면 끝나게` | 모든 피해 3배 |
| | `조작을 뒤집어` | 좌우 이동 반전 |
| | `전부 거대해져라` | 전원 1.6배. 리치도 함께 커진다 |
| | `시간을 늦춰라` | 슬로우 모션 |

### 리듬 배틀

룰 기믹 중 가장 극적인 것. 켜지면 상단에 박자 게이지가 뜨고,
**때린 순간이 박자에 맞았는지로 피해가 갈린다.**

| 판정 | 오차 | 피해 |
|---|---|---|
| `PERFECT!` | ±105ms | **2배** |
| `GOOD` | ±200ms | 1.25배 |
| `OFF BEAT…` | 그 밖 | **0.5배** |

마구 누르는 쪽이 손해가 되므로, 같은 조작으로 전혀 다른 게임이 된다.

### 한 문장에 두 가지를 쓰면 둘 다 걸린다

`달에서 한 방에 끝내자` 는 **장소와 규칙을 동시에** 말한다. 하나만 골라
버리면 플레이어가 쓴 말의 절반을 흘린 것이고, 그러면 다음부터는 짧게만
쓰게 된다 — 길게 쓸 이유가 없어지므로.

```
"달에서 한 방에 끝내자"        → 서든데스 + 달 표면
"전부 거대하게 만들고 느리게"   → 거대화 + 슬로우 모션
"용암 위에서 조작을 뒤집어"     → 용암 지대 + 조작 반전
```

막는 조합은 **맵 두 개**뿐이다. 지형·중력·배경을 두 번 바꾸면 되돌리기가
꼬인다. 그 외에는 같은 갈래라도 겹친다.

### 해석은 어떻게 하는가

**API 키 없이 동작한다.** 대회 제출 요건상 심사자가 별도 라이선스 없이
실행할 수 있어야 하므로, 해석기는 로컬 키워드 매칭으로 돌아간다.

- 못 알아들어도 **반드시 무언가는 일어난다.** 아무 일도 안 일어나면
  플레이어는 고장난 줄 안다
- **같은 문장은 늘 같은 결과.** 문장 해시로 고르므로 우연이 아니라 규칙으로 느껴진다
- 띄어쓰기를 떼고도 대조한다 — `한 방`과 `한방`은 같은 말이다
- **어떻게 읽었는지 화면에 보여준다** — `AI 해석: '한방'과 '달'을 함께 읽었다 · 확신 99%`

마지막 항목이 중요하다. 결과만 뜨면 알아들은 것인지 아무거나 고른 것인지
플레이어가 구별할 수 없고, 구별이 안 되면 이 게임의 축이 작동한다는 사실
자체가 전달되지 않는다.

외부 모델을 붙이더라도 `문장 → GimmickSpec` 이라는 계약은 그대로다.
`src/config/gimmicks.ts` 의 해석기만 갈아 끼우면 된다.

```bash
npm run test:prompt   # 해석기 단독 테스트 (브라우저 불필요)
```

## 연승 도전 — 이기면 그 자리에서 다음 상대

캐릭터 스무 명에 무대 넷을 만들어 놨는데, 한 번 켜서 한 판 하고 끝나면
그중 **다섯 명과 한 곳밖에** 못 본다. 만든 것의 4분의 3이 안 보이는 셈이다.

이기면 결과 화면에서 `SPACE` 한 번으로 다음 판이 시작된다.
**선택 화면으로 나가지 않아도 되는 것**이 핵심이다 — 나가는 순간 대부분은
거기서 그만둔다.

| 판이 넘어갈 때 바뀌는 것 | 어떻게 |
|---|---|
| 상대 셋 | 방금 싸운 셋을 뒤로 밀어 다시 뽑는다. 메커니즘은 여전히 셋 다 다르다 |
| 무대 | 앞 판과 다른 곳 |
| 봇 | 판단 주기 −45%, 반응 지연 −50%, 회피·강공격 비율 상승 (5판에서 최대) |
| 내 주가 | 이긴 순간의 값을 이어받는다 (하한 70% · 상한 150%) |

봇을 강하게 만드는 축은 여럿이지만 **판단 주기와 반응 지연만** 줄인다.
피해량이나 체력을 손대면 "봇이 잘한다"가 아니라 "봇이 치트를 쓴다"로
느껴지기 때문이다. 같은 규칙 안에서 더 빨리 판단할 뿐이다.

주가도 전부 회복시키지 않는다. 아슬아슬하게 이겼으면 다음 판도 아슬아슬하게
시작해야 연승이 쌓이는 맛이 난다. 다만 바닥에서 시작하면 그냥 끝나므로 하한을 뒀다.

3연승부터 칭호가 붙는다 — 연승 중 → 떡상 가도 → 상한가 행진 →
시장 지배자 → **전설의 큰손**.

## 무대 — 어디서 싸우는가

캐릭터를 바꾸는 것은 "내가 뭘 누르는가"를 바꾸고, 맵을 바꾸는 것은
"어디서 싸우는가"를 바꾼다. 둘은 다른 축이다. 발판 배치 하나만 달라져도
판이 통째로 달라진다 — 낮고 촘촘하면 도망칠 데가 없어 계속 붙어 싸우게 되고,
높고 성기면 이동 자체가 선택이 된다.

| 무대 | 특징 | 곡 |
|---|---|---|
| 🏛 **증권 거래소** | 표준 — 사다리처럼 이어진 다섯 발판 | 기준 |
| 🚁 **옥상 헬리패드** | 고공전 — 발판이 셋뿐, 사이가 멀다 | +3반음 · 1.05배 |
| 🖥 **서버실** | 난전 — 낮고 촘촘한 여섯 발판, 도망칠 데가 없다 | −2반음 · 1.09배 |
| 🌙 **달 표면** | 저중력(0.62) — 오래 뜨고 천천히 떨어진다 | −5반음 · 0.88배 |

**곡은 무대마다 조와 템포가 달라진다.** 네 곡을 따로 쓰지 않는 이유는
넷 다 어중간해지기 때문이다 — 같은 곡을 조만 옮겨도 "다른 곳에 왔다"는
인상은 충분히 나고, 곡 자체의 완성도는 하나에 몰아줄 수 있다.

매 판 **앞 판과 다른 곳**으로 보낸다. 무작위로만 두면 같은 맵이 두세 번
연달아 나오고, 그러면 "맵이 여러 개"라는 사실 자체가 전달되지 않는다.
시작할 때 이름과 한 줄 설명이 뜬다.

지면 높이·좌우 끝·장외선은 무대와 무관하게 **고정한다.** 봇의 절벽 판단,
아이템 낙하 위치, 투사체 소멸 범위가 전부 그 값을 기준으로 잡혀 있어서,
맵마다 바꾸면 맵 하나 늘릴 때마다 시스템 넷을 같이 손봐야 한다.

## 규칙

- 모든 캐릭터가 **주가 100%** 로 시작한다
- 타격에 성공하면 **공격자는 오르고 피격자는 내린다**
- **0% = 상장폐지(KO)**, **300% = 상한가**
- 장외로 떨어져도 즉시 상장폐지
- 마지막 1인이 승리 (1P vs 3AI)

### 봇도 자기 캐릭터를 쓴다

CPU 셋은 이름표만 다른 같은 봇이 아니다. 고유 메커니즘마다 **쓰는 법이 다르다.**

| 상대 | 봇이 하는 짓 |
|---|---|
| 빌 게이츠맨 | 지분을 4개까지 모았다가 블루스크린을 터뜨린다 |
| 스티브 잡스맨 | 스킬을 맞히면 열린 창에 곧바로 한 번 더 지른다 |
| 일론 머스크맨 | 공중 대시로 붙었다 뺀다. 장외에서도 부스터로 돌아온다 |
| 리누스 토발즈맨 | **피하는 대신 막는다.** 막아서 훔친 기술을 그대로 되돌려준다 |
| 패니 와이즈맨 | 풍선을 벌고 나면 맞기를 꺼려 도망 다닌다 |

맞는 쪽에서 그 캐릭터의 사용법을 배우게 하는 것이 목적이다.
성격은 `src/config/aiPersona.ts` 한 장에 모여 있고, `npm run test:ai` 가 검사한다.

### 떡상 시스템

주가가 오를수록 강해진다. 맞을수록 약해지는 게 아니라, **때릴수록 강해지는** 구조라
한 번 흐름을 타면 몰아칠 수 있다.

| 주가 | 등급 | 효과 |
|---|---|---|
| 0% | 상장폐지 | KO |
| 1~49% | 위기 | 붉은 깜빡임 |
| 50~100% | 보통 | 기본 |
| 101~149% | 상승 | 공격력 +10%, 초록 오라 |
| 150~199% | 떡상 1단계 | 공격력 +25%, 이속 +10%, 불꽃 |
| 200~299% | 떡상 2단계 | 공격력 +45%, 이속 +15%, 쿨다운 -20% |
| 300% | 초! 떡상 | 공격력 +70%, 전 능력치 상승 |

### 캐릭터

기본 공격도 캐릭터마다 다르다. 속도·리치·한방이 서로 맞물린다.
(아래는 첫 다섯 명. 나머지 열다섯 명은 [로스터 20명](#로스터-20명) 참고)

| 캐릭터 | 스타일 | 패시브 | 시그니처 |
|---|---|---|---|
| 빌 게이츠맨 | 견제 — 리치 길고 묵직 | 독점 흡수 (150% 흡수) | 블루스크린 (투사체 + 스턴) |
| 스티브 잡스맨 | 한방 — 발동·회복 빠름 | 현실 왜곡 (30% 확률 2배) | 스포트라이트 펀치 |
| 일론 머스크맨 | 속도 — 48ms 연타 | 변동성 폭발 (200%↑ 2배) | 로켓 드롭 |
| 리누스 토발즈맨 | 리치 — 최장거리 최저속 | 오픈소스 (50%↓ 1.5배) | 커널 패닉 (지속 피해) |
| 패니 와이즈맨 | 도박 — 최속 + 최강 | 밈 파워 (10~30% 랜덤) | 리츠고! (주가 도박) |

기술 이름과 모션은 **그 인물의 캐릭터성에서 먼저 나온다.** 이 게임의 정체성이
패러디이므로, 수치보다 "그 사람이라면 이렇게 싸운다"가 먼저다.

| 커맨드 | 빌 게이츠맨 | 스티브 잡스맨 | 일론 머스크맨 | 리누스 토발즈맨 | 패니 와이즈맨 |
|---|---|---|---|---|---|
| `J` `J` `J` | 잽 → 더블 클릭 → **강제 종료** | 훅 → 스트레이트 → **슬라이드 넘기기** | 트윗 연사 → 리트윗 → **커뮤니티 노트** | 코드 리뷰 → 변경 요청 → **전면 재작성** | 광대 펀치 → 저글링 → **풍선 터뜨리기** |
| `K` `K` | 독점 킥 → **인수 합병** | 현실 왜곡 강타 → **단종 선언** | 부스터 차지 → **단수 분리** | 커밋 해머 → **메인라인 병합** | 올인 스윙 → **광대의 초대** |
| `W`+`J` | 강제 업데이트 | 원 모어 씽 | 스타링크 발사 | 머지 리퀘스트 | 붉은 풍선 |

| `W`+`K` | Ctrl+Alt+Del | 키노트 어퍼 | 팰컨 이륙 | force push | 점프 스케어 |
| `S`+`K` | 반독점 소송 | 심사 반려 | 착륙 실패 | 롤백 슬램 | 하수구 개봉 |
| 대시 중 | 시장 진입 | 기습 발표 | 하이퍼루프 | 강제 푸시 | 하수구 질주 |
| 공중 `S`+`K` | 강제 재부팅 | 가격 인하 | 대기권 재진입 | 커널 강림 | 떠내려가기 |

### 스무 명을 한 표에 올린다 — `npm run balance`

다섯 명일 때는 다 해 보고 감으로 맞출 수 있었다. 스무 명이면 맞붙는 조합만
190가지다. 사람이 다 해 볼 수 없고, 안 해 보면 한 명이 두 배 센 채로
제출된다 — 그 한 명 때문에 나머지 열아홉이 의미를 잃는다.

그런데 이 게임의 수치는 전부 데이터다. 기술마다 피해·선딜·판정·후딜이
있으니 초당 피해가 계산되고, 패시브에는 기대 배율이, 스탯에는 무게가 있다.
**공격 · 기동 · 생존 · 사거리** 네 축을 표준편차 단위로 놓고 합산한다.

```
캐릭터               공격      기동      생존      사거리       종합
제프 베조스            -1.25    0.19    1.30    1.38     1.6  ◀ 상위
...
동학 개미             -0.96    2.22   -1.74   -1.00    -1.5  ◀ 하위
```

선은 두 개다. **1.5σ는 "봐 둘 것"**(일부러 극단으로 만든 캐릭터가 걸리는 것은
정상), **2.5σ는 "이건 사고"** 이며 검사를 실패시킨다. 하나만 두면 너무 자주
울려 무시하게 되거나 영영 안 울린다.

통계와 별도로 규칙 검사도 한다 — 초당 피해 범위, 판정 길이, 사거리, 스킬
쿨다운, 연속기가 뒤로 갈수록 세지는가. 이쪽은 설계 의도일 수 없는 종류
(복붙하다 안 고친 숫자)라 무조건 실패로 잡는다.

> 이 표는 **모델이지 승률이 아니다.** 판정 모양·봇 성격·맵은 계산에 없다.
> "누가 이긴다"가 아니라 "누가 혼자 튄다"만 말한다.

### 결과 화면 — 무슨 일이 있었는지 남긴다

판이 끝나면 네 명의 전적표가 뜬다. 준 피해 · 맞은 피해 · KO · 최고 주가 ·
**가장 많이 쓴 기술.** 준 피해 순으로 세우고, 1위에 왕관을, 내 줄에는
캐릭터 색 배경을 깐다.

캐릭터가 스무 명인 게임에서는 내가 뭘 했는지가 다음 판의 선택을 만든다.
"이 캐릭터로 992를 넣었네", "가장 많이 쓴 건 이용약관 동의였네" — 둘 다
다음에 누구를 고를지에 영향을 준다. 그 정보가 없으면 스무 명이 그냥
스무 개의 이름으로 남는다.

### 구조

```
src/
├── config/      게임 상수, 캐릭터·아이템·스프라이트 데이터
├── scenes/      Boot → Title → Select → Battle

├── systems/     Stock · Combat · Projectile · Item · AI · Sound · EventBus
│                PromptOrb · Gimmick · Rhythm (프롬프트 기믹)

└── types/       공유 타입
tools/           스프라이트 시트 전처리, 스모크 테스트, 해석기 테스트
```

캐릭터 성능은 전부 `src/config/characters.ts` 의 데이터다.
시스템 간 통신은 `EventBus` 를 통한다.

### 에셋

외부 에셋 의존을 최소화했다. **그림이 한 장도 없어도 게임은 끝까지 돌아간다.**
있는 그림은 그 위에 덮이고, 없는 자리는 코드로 그린 화면이 그대로 대신한다.

- **사운드**: 파일 없음. Web Audio API로 실시간 합성 (`src/systems/SoundSystem.ts`)
- **캐릭터**: 스프라이트 시트가 있으면 사용, 없으면 Phaser 도형으로 코드 드로잉
- **이펙트**: 전부 코드 생성
- **배경 · 타이틀 · UI**: 아래 경로에 넣으면 새로고침만으로 적용된다

| 넣는 곳 | 무엇 | 없으면 |
|---|---|---|
| `public/bg/stage_*.png` | 스테이지 배경 5종 | 코드로 그린 캔들차트 배경 |
| `public/ui/ui_title_bg·logo.png` | 타이틀 화면 | 글자로 그린 타이틀 |
| `public/ui/ui_select_bg.png` | 캐릭터 선택 배경 | 코드로 그린 배경 |
| `public/ui/ui_result_bg.png` | 결과 화면 배경 | 검은 반투명 막 |
| `public/ui/ui_item_icons.png` | 아이템 아이콘 6칸 띠 | 이모지 |
| `public/ui/ui_prompt_orb.png` | 프롬프트 오브 4칸 띠 | 발광 원 + 링 |

전처리가 필요 없다. 크기는 아무래도 좋고(비율을 지켜 화면을 덮도록 맞춘다),
띠 그림은 게임이 가로로 똑같이 나눠 쓰며, 투명이 안 돼서 마젠타(#FF00FF)
배경으로 온 그림은 자동으로 누끼를 딴다. 프롬프트는 `npm run prompts` 가
`art-source/prompts/scenes/` 에 만들어 둔다 (`src/config/artAssets.ts` 가 표다).

#### 손으로 안 하고 한 번에

프롬프트를 열어 복사 → 웹에 붙여넣기 → 기다리기 → 내려받기 → 이름 바꾸기 →
폴더에 옮기기. 한 장에 여섯 단계고, 다 하면 46장이다.
그중 사람이 판단할 것은 "이 그림이 마음에 드는가" 하나뿐이므로 나머지는 넘긴다.

```bash
cp .env.example .env.local     # GEMINI_API_KEY 를 채운다 (커밋되지 않는다)

npm run art                    # 배경 5 + UI 6 — 아직 없는 것만
npm run art -- gates           # 빌 게이츠맨 묶음 7장
npm run art -- --all           # 46장 전부
npm run art -- exchange --force  # 마음에 안 드는 한 장만 다시
npm run art -- --dry           # 뭘 만들지만 보고 끝
```

같은 프롬프트 파일을 읽어 보내고, 받은 그림을 게임이 읽는 경로에 바로 쓴다.
**이미 있는 그림은 건너뛴다** — 어제 마음에 들어 남겨둔 것을 덮어쓰지 않는다.

캐릭터 묶음을 뽑을 때는 **1번 묶음 결과를 2~7번에 참조 이미지로 함께 보낸다.**
글로만 시키면 묶음마다 옷 색이 바뀌고 무기가 사라져, 이어 붙이면 시트가 아니라
여러 명이 번갈아 나오는 애니메이션이 된다.

#### 무료로 쓰려면

이미지 생성에 무료 티어가 없는 곳이 대부분이라, 공짜인 곳도 붙여 뒀다.

```bash
ART_PROVIDER=pollinations npm run art -- scenes   # 키 없이 바로
ART_PROVIDER=cloudflare   npm run art -- scenes   # 하루 무료 할당량
ART_PROVIDER=huggingface  npm run art -- scenes   # 무료 한도
```

| 제공자 | 키 | 참조 이미지 | 쓸 곳 |
|---|---|---|---|
| `gemini` (기본) | 필요 · 유료 | ○ | 캐릭터 시트 · 전부 |
| `pollinations` | 불필요 | ✕ | 배경·UI |
| `cloudflare` | 계정+토큰 | ✕ | 배경·UI |
| `huggingface` | 토큰 | ✕ | 배경·UI |

**캐릭터 시트는 무료 모델로 거의 안 나온다.** "여섯 칸을 세고, 일곱 묶음 내내
같은 인물을 유지한다"는 그림 실력이 아니라 지시를 따르는 능력이고, 참조 이미지를
받을 수 있어야 한다. 글→그림 모델(FLUX·SD)은 묶음마다 다른 사람을 그린다.
`npm run art` 가 시트를 무료 제공자로 뽑으려 하면 먼저 말린다.

#### 돈 안 쓰고 절반만 자동으로

이미지 생성 API는 무료 티어가 없다(배경·UI 11장에 $0.43~0.74).
웹에서 받는 것은 공짜이므로, 그 뒤의 **이름 바꾸고 폴더 찾아 넣는 일**만 넘긴다.

```bash
npm run art:in            # 순서대로 하나씩
npm run art:in -- scenes  # 배경·UI만
npm run art:in -- --list  # 어디까지 채웠는지 보기
```

**사람이 하는 일은 `Ctrl+V` → 받기, 이게 전부다.**

도구가 프롬프트를 클립보드에 넣어 두고 다운로드 폴더를 지켜본다. 새 그림이
떨어지면 정해진 이름으로 정해진 자리에 옮기고 **다음 프롬프트를 클립보드에
채워 넣는다.** 터미널로 돌아올 필요가 없다.

```
[1/11] 배경 · 증권 거래소
   프롬프트를 클립보드에 넣었습니다. 나노바나나에 Ctrl+V 하고 받으세요.
   ✓ Gemini_Generated_Image_a1b2.png → public/bg/stage_exchange.png

[2/11] 배경 · 달 표면
   프롬프트를 클립보드에 넣었습니다. …
```

`s` 건너뛰기 · `q` 끝내기. 중간에 멈춰도 다시 실행하면 남은 자리부터 이어서 한다.
찾는 곳은 `ART_INBOX` → `art-source/inbox/` → 다운로드 폴더 순이다.

#### 넣은 다음엔 반드시 줄인다

```bash
npm run art:opt            # 아직 안 줄인 그림만 webp로
npm run art:opt -- --report  # 지금 무엇이 얼마나 무거운지
```

생성기가 주는 것은 무손실 PNG다. 배경 한 장이 6MB고, 그대로 올리면
**심사자의 브라우저에서 로딩만 수십 초**가 걸린다. 그건 그 시점에
"안 켜지는 게임"과 같은 말이다.

해상도는 그대로 두고 포맷만 바꾼다. 눈에 보이는 손실 없이 20.6MB → 1.5MB,
배포본 전체로는 **32MB → 2.9MB**가 된다.

- 원본 PNG는 지우지 않는다 — 다시 뽑을 때 비교할 것이 있어야 한다
- 게임은 webp가 있으면 그쪽을, 없으면 PNG를 읽는다.
  방금 폴더에 떨어뜨린 그림도 줄이기 전에 바로 보인다
- 배포본(`dist`)에는 webp만 실린다 (`vite.config.ts`)

스테이지 배경은 **맵 기믹과 짝지어져** 있다. "달로 보내줘"를 입력하면 중력만
바뀌는 게 아니라 배경까지 달 표면으로 갈렸다가, 기믹이 끝나면 되돌아온다.

## 함께 작업하기

이 저장소는 **여러 대에서 같은 브랜치**로 작업한다 (노트북 VS Code + 클라우드 세션).
서로 밀어내지 않으려면 두 가지만 지키면 된다.

### 1. 올리기 전에 항상 당긴다

```bash
git config pull.rebase true    # 처음 한 번만. 작업 폴더마다 따로 해야 한다
git pull                       # 커밋한 뒤, 밀기 전에
npm test && npm run build      # 남의 변경과 합쳐진 상태로 한 번 확인
git push
```

`pull.rebase` 를 켜 두면 "Merge branch…" 커밋이 쌓이지 않아 기록이 읽힌다.

### 2. 같은 자리를 동시에 고치지 않는다

| 영역 | 파일 |
|---|---|
| 전투·커맨드 | `src/characters/BaseCharacter.ts`, `src/systems/CombatSystem.ts` |
| 프롬프트 기믹 | `src/systems/{PromptOrb,Gimmick,Rhythm}System.ts`, `src/config/gimmicks.ts` |
| 캐릭터 데이터 | `src/config/characters.ts` |
| 봇 | `src/systems/AISystem.ts`, `src/config/aiPersona.ts` |
| 씬·UI | `src/scenes/*.ts`, `src/ui/*.ts` |
| 아트 도구 | `tools/art-*.mjs`, `tools/gen-*.mjs`, `tools/*-sheet*.mjs` |

`src/config/gameConfig.ts` 와 `src/types/index.ts` 는 누구나 건드리는 공용 파일이다.
**추가만 하고 기존 줄은 옮기지 말 것.** 그러면 같은 파일을 둘이 고쳐도 자동으로 합쳐진다.

### 3. 그림은 한 사람만 다시 만든다

PNG·WebP는 줄 단위로 합칠 수 없다. 둘이 같은 그림을 새로 뽑으면 반드시 충돌한다.
충돌하면 합치려 들지 말고 한쪽을 고른 뒤 다시 생성한다.

```bash
git checkout --theirs public/bg/stage_moon.png   # 상대 것으로
npm run art:opt                                  # webp 다시 만들기
```

줄바꿈(CRLF/LF)과 이진 파일 처리는 `.gitattributes` 가 잡아 준다 — 윈도우와
리눅스를 오갈 때 파일 전체가 바뀐 것처럼 보이는 사고를 막기 위한 것이다.

## 개발

```bash
npm run dev        # 개발 서버
npm run typecheck  # 타입 검사
npm run build      # 프로덕션 빌드
npm run smoke      # 스모크 테스트 (dev 서버 실행 중이어야 함)
npm run test:prompt # 프롬프트 해석기 테스트 (브라우저 불필요)
npm run test:sheet  # 스프라이트 시트 파이프라인 테스트 (묶음 합치기 → 규격 판별)
npm run test:ai     # 봇 성격 테스트 (캐릭터별 스킬 판단)
npm run test:char   # 로스터 정합성 (명단 4곳 일치 · 기술 이름 280개 중복 없음)
npm run balance     # 밸런스 — 스무 명을 네 축으로 재고 혼자 튀는 캐릭터를 찾는다
npm run char:new -- <id> "<이름>" "<실존 인물>" [메커니즘]   # 캐릭터 뼈대 생성
npm test            # 위 전부 + 타입 검사 한 번에
npm run prompts    # 프롬프트 생성 (캐릭터 20명 × 7묶음 + 스테이지·UI 11)
npm run art        # 그 프롬프트로 이미지 생성 → 제자리에 저장 (API 키 필요, 유료)
npm run art:in     # 웹에서 받은 그림을 제자리에 정리 (공짜)
npm run art:opt    # 넣은 그림을 webp로 줄임 (배포 무게 32MB → 2.9MB)
npm run docs       # 제출용 PDF 생성 (docs/submission/*.html → pdf/)
npm run sheet:merge -- <key>            # 받은 묶음 이미지를 시트 한 장으로 합침
npm run sheet -- <입력.png> <출력.png>   # 스프라이트 시트 전처리(단일 파일)
npm run sheet -- <입력.png> <출력.png> --grid 5x3 --label-band 0.13
                                        #   칸을 못 가르거나 라벨이 남을 때
```

`npm run smoke` 는 타이틀 → 선택 → 전투 → 이동/점프/공격/커맨드 무브/연속기/프롬프트 기믹/
스킬/방어/대시 → 결과 경로를 자동으로 밟으며 단계별 스크린샷을 남기고
콘솔 오류를 검사한다.

그림으로 단정할 수 없는 것은 **상태로** 대조한다.
커맨드 무브는 실제로 발동한 기술 이름으로, 프롬프트 기믹은
"입력한 문장 → 실제로 걸린 룰·중력값"으로 확인하므로,
`W+K`를 눌렀는데 중립 강공격이 나가거나, `달로 보내줘`가 중력을 안 바꾸거나,
머스크맨의 공중 대시가 조용히 죽는 회귀는 바로 잡힌다.

무대 넷을 하나씩 실제로 세워 발판 수와 중력을 대조하고, 전투 종료까지 가서
전적이 채워졌는지 확인한다. 결과 화면은 판이 끝나야만 나오므로 거기까지
가지 않으면 통째로 미검증이었다. BGM도 마찬가지 — 소리는 스크린샷에 안
남으므로 시퀀서 스텝이 실제로 늘어나는지를 본다.

새 스프라이트 시트를 넣는 방법은 [`docs/art-spec.md`](docs/art-spec.md) 참고.
커맨드·연속기에 아이템을 쥔 손, 프롬프트 시전, 도발, 기절까지 더해
새 시트는 **42프레임(7×6) V3 규격**이다. 한 장에 42칸을 그리게 하면 그림이 무너지므로
**6칸씩 7묶음**으로 끊어 뽑는다 — `npm run prompts` 가 묶음별 프롬프트를 만들고,
`npm run sheet:merge -- <key>` 가 받은 이미지들을 시트 한 장으로 합친다.

규격(V1 15 / V2 30 / V3 42)은 **시트의 프레임 수를 보고 자동으로 정해진다.**
이미 등록된 캐릭터라면 새 시트를 `public/sprites/` 에 덮어쓰는 것만으로 갈아 끼워지고,
기존 15프레임 시트도 그대로 동작한다 (없는 포즈는 가장 가까운 그림으로 대체된다).

**7묶음을 다 뽑지 않아도 된다.** 캐릭터 20명 × 7묶음 = 140장은 현실적인
목표가 아니므로, **1(이동) · 3(지상 연속기) · 7(피격·결과·초상)** 세 묶음만
뽑은 18칸 시트도 그대로 게임에 들어간다. 늘 화면에 있는 그림은 이 셋에 다
들어 있고, 나머지 포즈는 대체 사슬이 메운다. 스무 명을 60장으로 채울 수 있다.
나중에 묶음을 더 뽑아 다시 합치면 게임 쪽은 손댈 것 없이 그 포즈가 살아난다.
작업 순서는 `art-source/prompts/00-README.md` 에 있다 (`npm run prompts` 가 갱신).
