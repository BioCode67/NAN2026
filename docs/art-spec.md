# 아트 생성 규격

캐릭터 스프라이트 시트와 아이템 아이콘을 AI로 생성할 때 쓰는 지시문이다.
**캐릭터 이름과 외형 설명만 바꿔서** 그대로 붙여넣으면 된다.

> **양식은 고정, 캐릭터만 교체.**
> 프롬프트는 "공통 뼈대 + 캐릭터별 빈칸" 구조다. 아트 스타일·격자 규격·
> 프레임 순서는 전 캐릭터가 글자 하나까지 같고, 바뀌는 것은 외형 설명과
> 기술 다섯 줄뿐이다. 그래야 캐릭터를 늘려도 화풍이 따로 놀지 않는다.
> 실제 빈칸은 `tools/gen-sheet.mjs` 의 `CHARACTERS` 표에 있다.

---

## 0. 프레임 규격 (V2 — 4행 x 6열, 24프레임)

커맨드 무브(W+J / S+K / 공중 급강하 …)가 생기면서 그림도 그만큼 필요해졌다.
**새로 뽑는 시트는 전부 아래 24프레임 규격으로 만든다.**

| # | 프레임 | 게임 안 용도 | 커맨드 |
|---|--------|--------------|--------|
| 0 | IDLE | 대기 | — |
| 1 | WALK | 걷기 | — |
| 2·3 | RUN_A·RUN_B | 달리기 사이클 | — |
| 4 | JUMP | 상승 중 | SPACE |
| 5 | FALL | 하강 중 | — |
| 6 | ATTACK_J | 약공격 | J |
| 7 | ATTACK_J_UP | 상단 견제 (띄우기) | W+J |
| 8 | ATTACK_J_DOWN | 하단 견제 (저공) | S+J |
| 9 | ATTACK_K | 강공격 | K |
| 10 | ATTACK_K_UP | 상승 강타 (자기도 뜬다) | W+K |
| 11 | ATTACK_K_DOWN | 내려찍기 (광역) | S+K |
| 12 | AIR_J | 공중 견제 | 공중 J |
| 13 | AIR_K | 공중 회전 | 공중 K |
| 14 | AIR_DIVE | 급강하 찍기 | 공중 S+J/K |
| 15 | SKILL_L | 스킬 시전 | L |
| 16 | SKILL_L2 | 스킬 방출 | L |
| 17 | SKILL_FX | **캐릭터 없이 이펙트만** — 투사체·착지 충격파 | — |
| 18 | HIT | 피격 | — |
| 19 | KNOCKBACK | 날아감 | — |
| 20 | GUARD | 방어 | S |
| 21 | DASH | 대시 | AA / DD |
| 22 | WIN | 승리 | — |
| 23 | LOSE | 패배 | — |

이 순서는 `src/config/spriteSheets.ts` 의 `LAYOUT_V2` 와 1:1로 대응한다.
시트를 뽑고 나면 등록은 한 줄이면 끝난다.

```ts
musk: {
  key: 'elonmusk',
  displayHeight: 116,
  frameRate: 10,
  explosionFrame: LAYOUT_V2_FX_FRAME,
  poses: LAYOUT_V2,
},
```

### 아직 옛 시트(V1, 15프레임)를 쓰는 캐릭터는?

그대로 돌아간다. 없는 포즈는 `POSE_FALLBACK` 사슬을 따라
가장 가까운 그림으로 대체된다 (상단기 → 기본 약공격 등).
**그림이 없다고 기술이 막히지는 않는다.** 다만 상단기와 하단기가
같은 그림으로 나오므로, 차별화를 눈으로 보려면 V2로 다시 뽑아야 한다.

## 1. 캐릭터 스프라이트 시트

### 아트 디렉션 — 먼저 읽을 것

1차 생성물이 **캐리커처처럼 나와 게임 캐릭터로 안 보이는 문제**가 있었다.
원인은 비율이다. "SD 스타일"이라고만 쓰면 생성기가 거의 실사 비율(6~7등신)로
그린다. 게임 캐릭터는 **실루엣만 봐도 누군지 구분되어야** 한다.

반드시 명시할 것:

- **2~2.5등신**. 머리가 몸통+다리를 합친 것과 비슷하게 크다
- **과장된 표정** — 눈을 부릅뜨거나 이빨을 드러내는 등 감정이 극단적
- **굵고 진한 검은 외곽선** — 배경에서 캐릭터가 튀어나와 보여야 한다
- **채도 높은 색** — 어두운 배경 위에 올라간다
- **액션 프레임은 만화적으로 과장** — 팔다리가 늘어나고 스피드선이 붙는다
- **상징 소품을 크게** — 그 인물이라고 바로 알아볼 수 있게

### 지시문 (복붙)

```
2D 대전 격투 게임용 스프라이트 시트를 만들어줘.

[캐릭터] <이름>을 극단적으로 과장한 SD 도트 캐릭터.
<외형 설명: 옷 색, 머리 모양, 안경/수염 등>
<엽기 포인트: 아래 캐릭터별 표 참고>

[아트 스타일 — 중요]
- 2~2.5등신. 머리가 몸 전체만큼 크게. 실사 비율 금지
- 표정을 극단적으로 과장할 것 (부릅뜬 눈, 드러낸 이빨, 광기)
- 굵고 진한 검은 외곽선. 어두운 배경에서 실루엣이 확실히 분리될 것
- 채도 높고 대비 강한 색
- 액션 프레임은 만화처럼 과장 (늘어난 팔다리, 스피드선, 임팩트)
- 귀엽고 얌전한 캐리커처가 아니라, 시끄럽고 우스꽝스러운 게임 캐릭터

[필수 규칙]
- 배경: 완전 투명 PNG. 체크무늬를 그려 넣지 말 것.
  (투명이 안 되면 순수 마젠타 #FF00FF 단색으로. 캐릭터에는 이 색을 쓰지 말 것)
- 글자 금지: 프레임 이름/라벨/워터마크를 이미지에 넣지 말 것
- 4행 x 6열 격자, 총 24칸. 칸 구분선을 그리지 말 것
- 프레임 사이 간격은 캐릭터 폭의 20% 이상 확보
- 모든 프레임에서 캐릭터가 오른쪽을 향할 것
- 모든 프레임 크기·비율 동일, 발끝을 같은 높이에 맞출 것
- 이펙트(기술 효과)가 옆 프레임을 침범하지 않게 할 것
- 오른손은 물건을 쥘 수 있게 비워두고, 손목 높이를 프레임마다
  크게 흔들리지 않게 유지할 것 (아이템 장착 대비)
- 24장 전부 같은 캐릭터로 보일 것. 옷 색·머리·무기를 프레임마다 바꾸지 말 것

[동작 방향 규칙 — 게임 조작과 직결된다]
- 위(UP) 계열은 시선·무기·팔이 명확히 위를 향할 것
- 아래(DOWN) 계열은 몸을 확실히 낮추고 무기가 지면 쪽을 향할 것
- 공중(AIR) 계열은 두 발이 지면에서 떨어져 있을 것
- 같은 버튼의 위/아래 동작이 서로 구분되게 자세를 확실히 다르게 그릴 것

[프레임 24개, 이 순서로]
1행: IDLE, WALK, RUN_A, RUN_B, JUMP(솟는 중), FALL(떨어지는 중)
2행: ATTACK_J, ATTACK_J_UP(<위 견제>), ATTACK_J_DOWN(<아래 견제>),
     ATTACK_K, ATTACK_K_UP(<상승기>), ATTACK_K_DOWN(<내려찍기>)
3행: AIR_J, AIR_K, AIR_DIVE(<급강하>),
     SKILL_L(기 모으기), SKILL_L2(방출), SKILL_FX(이펙트만, 캐릭터 없이)
4행: HIT, KNOCKBACK, GUARD, DASH, WIN, LOSE
```

`<...>` 자리에 아래 표의 캐릭터별 기술 설명을 넣는다.
기술 이름은 `src/config/characters.ts` 의 `moves` 와 **반드시 일치시킨다** —
그림과 판정이 어긋나면 "왜 이 모션에서 이 판정이 나오지?"가 된다.

### 캐릭터별 무기 + 엽기 포인트

**무기는 전투 스타일과 일치해야 한다.** 리치가 긴 캐릭터가 단검을 들면
플레이 감각과 그림이 따로 논다. 아래 배정은 `characters.ts` 의
실제 수치(리치·발동 속도·위력)에서 나온 것이다.

| 캐릭터 | 무기 | 전투 스타일 근거 | 넣을 문장 |
|---|---|---|---|
| **빌 게이츠맨** | 거대 **해머** (돈다발을 묶어 만든) | 리치 94, 발동 195ms — 느리고 묵직 | 지폐 뭉치를 철사로 감아 만든 거대한 해머를 어깨에 걸쳤다. 안경 렌즈에 파란 블루스크린이 번쩍이고, 세상을 다 사버린 듯한 능글맞은 미소. |
| **스티브 잡스맨** | **광선검** (흰 손잡이, 무지개 칼날) | 발동 62ms, 회복 300ms — 한방·근접 압박 | 흰 알루미늄 손잡이에서 무지개빛 광선 칼날이 뻗어 나온다. 검은 터틀넥, 몸 뒤로 후광. 눈은 광신도처럼 번뜩인다. |
| **일론 머스크맨** | **쌍권총** (로켓 탄창) | 약공격 발동 48ms — 최속 연타 | 양손에 작은 로켓이 장전된 쌍권총. 등에 부스터를 매달고 불꽃을 뿜는다. 두 눈이 도지코인 모양, 씩 웃는 입. |
| **리누스 토발즈맨** | **대검** (거대한 양손검) | 리치 102 — 최장거리, 최저속 | 자기 키만 한 거대한 양손 대검. 칼날에 초록 터미널 글자가 흐른다. 펭귄 모자를 쓰고 잔뜩 인상 쓴 채 이빨을 드러낸다. |
| **패니 와이즈맨** (페니와이즈) | **도끼** (양날 대형 도끼) | 강공격 25 — 최강 한 방, 최단 리치 | 자기 몸보다 큰 양날 도끼를 휘두른다. 창백한 흰 분칠 얼굴, 붉게 솟구친 머리, 귀까지 찢어진 입에 뾰족한 이빨. 한 손에 붉은 풍선. |

무기는 지시문의 `<외형 설명>` 자리에 함께 넣는다.
프레임별로 무기가 어떻게 보여야 하는지는 아래 표를 참고.

| 프레임 | 무기 |
|---|---|
| IDLE / WALK / RUN | 어깨에 걸치거나 손에 늘어뜨림 |
| JUMP / FALL / DASH | 뒤로 젖혀 관성이 느껴지게 |
| ATTACK_J | 짧게 찌르거나 견제 — 작게 |
| ATTACK_K | 크게 휘두름 — 궤적 잔상 필수 |
| *_UP | 무기 끝이 하늘을 향함. 시선도 위 |
| *_DOWN | 무릎을 굽혀 몸을 낮추고 무기는 지면으로 |
| AIR_DIVE | 무기를 앞세워 머리부터 내리꽂는 자세 |
| SKILL_L / SKILL_L2 | 무기가 빛나며 에너지 방출 |
| SKILL_FX | 무기도 캐릭터도 없이 **에너지 이펙트만** |
| HIT / KNOCKBACK | 무기를 놓칠 듯 흔들림 |
| GUARD | 무기를 세워 막는 자세 |
| WIN / LOSE | 치켜들기 / 떨어뜨리기 |

### 캐릭터별 커맨드 기술 (그림 = 게임 데이터)

`tools/gen-sheet.mjs` 의 `CHARACTERS[*].moves` 에 그대로 들어 있는 값이다.
캐릭터를 추가할 때 이 다섯 칸을 채우는 것이 곧 캐릭터성을 정하는 일이다.

| 캐릭터 | W+J | S+J | W+K | S+K | 공중 S+K |
|---|---|---|---|---|---|
| **빌 게이츠맨** | 강제 업데이트 | 기부금 살포 | Ctrl+Alt+Del | 반독점 소송 | 강제 재부팅 |
| **스티브 잡스맨** | 원 모어 씽 | 씬 앤 라이트 | 키노트 어퍼 | 심사 반려 | 가격 인하 |
| **일론 머스크맨** | 스타링크 발사 | 보링 컴퍼니 | 팰컨 이륙 | 착륙 실패 | 대기권 재진입 |
| **리누스 토발즈맨** | 머지 리퀘스트 | rm -rf | force push | 롤백 슬램 | 커널 강림 |
| **패니 와이즈맨** | 붉은 풍선 | 하수구의 손 | 점프 스케어 | 하수구 개봉 | 떠내려가기 |

기술은 수치가 아니라 **그 인물이라면 어떻게 싸울까**에서 먼저 나온다.
이 게임의 정체성이 패러디이므로, 이름과 그림이 인물을 떠올리게 하지 못하면
아무리 손맛이 좋아도 다른 게임과 구분되지 않는다.

### 왜 이 항목들인가

실제로 겪은 문제에서 나온 규칙이다.

| 규칙 | 안 지켰을 때 |
|---|---|
| 투명 배경 | 체크무늬가 픽셀로 칠해져 오면 배경 분리에 시간이 든다. 반투명 이펙트는 복구 불가 |
| 라벨 금지 | `IDLE` 같은 글자가 게임 화면에 함께 렌더된다 |
| 프레임 간격 | 인접 프레임이 한 덩어리로 붙어 잘못 잘린다 |
| 방향 통일 | 캐릭터마다 좌우 반전이 어긋난다 (`facesLeft` 수동 지정 필요) |
| 발끝 정렬 | 애니메이션 중 캐릭터가 위아래로 튄다 |
| 오른손 비우기 | 나중에 아이템을 손에 쥐게 하려면 시트를 다시 뽑아야 한다 |

### SKILL_L2 와 SKILL_FX 는 역할이 다르다

V1(15프레임)에서는 한 칸으로 두 가지를 겸해야 했지만, V2에서는 나눴다.

- **SKILL_L2** — 캐릭터가 기술을 방출하는 순간. SKILL_L과 이어 붙여 2프레임 애니메이션이 된다
- **SKILL_FX** — 캐릭터 없이 이펙트만. 두 곳에서 쓴다
  - 투사체 스프라이트 → `characters.ts`의 `moves.skill.projectile.frame`
  - 착지 충격파 → `spriteSheets.ts`의 `explosionFrame`

`SKILL_FX` 에 캐릭터가 그려져 오면 화면에 작은 분신이 날아다닌다.
"캐릭터를 그리지 말 것"을 반드시 명시할 것.

## 2. 자동 생성 (권장)

프롬프트를 손으로 붙여넣지 않고 한 줄로 끝낼 수 있다.
`tools/gen-sheet.mjs` 가 위 규격과 캐릭터별 무기·엽기 포인트를 담고 있어,
**생성 → 배경 제거 → 크롭 → 균일 격자 재배치**까지 자동으로 처리한다.

```bash
# 1) API 키 발급: https://aistudio.google.com/apikey
$env:GEMINI_API_KEY = "발급받은키"      # PowerShell
export GEMINI_API_KEY=발급받은키         # bash

# 2) 실행
npm run gen -- gates          # 한 명
npm run gen -- --all          # 5명 전부
npm run gen -- gates --dry    # 프롬프트만 출력 (수동으로 쓸 때)
npm run gen -- --all --save   # 프롬프트를 파일로 저장 (웹 UI에 붙여넣을 때)
```

`--save` 는 `art-source/<key>_prompt.txt` 로 떨어진다.
API 키 없이 나노바나나 웹 화면에 그대로 붙여넣어 쓰는 용도다.

결과가 마음에 안 들면 그냥 다시 돌리면 된다. 같은 프롬프트도 매번 다르게 나온다.

> 유료 API 사용료는 참가자 부담이다 (대회 FAQ).
> 모델을 바꾸려면 `GEMINI_IMAGE_MODEL` 환경변수를 쓴다.

## 3. 수동 변환

이미 시트가 있으면 전처리만 돌린다.

```bash
npm run sheet -- art-source/<이름>_sheet.png public/sprites/<key>.png
```

세 가지 입력을 모두 처리한다.

- 투명 PNG → 알파 그대로 사용 (가장 깨끗)
- 단색 배경(마젠타 등) → 그 색 제거
- 체크무늬 시안 → 두 톤 제거

출력 로그 마지막 줄에 검출된 프레임 수가 찍힌다.
**24개가 나왔으면** `src/config/spriteSheets.ts` 에 `poses: LAYOUT_V2` 로 등록하면 끝이다.
개수가 어긋나면 프레임이 붙거나 잘렸다는 뜻이므로, 손으로 매핑을 맞추기보다
시트를 다시 뽑는 편이 빠르다.

해상도를 바꾸려면 `MAX_FRAME_H=320 node tools/process-sheet.mjs ...`

## 4. 아이템 아이콘

아이템은 **캐릭터 몸에 그리지 않는다.** 캐릭터 주변 오라 + 머리 위 아이콘으로
표현하므로, 아이콘 하나만 있으면 된다.

```
게임 UI용 아이템 아이콘을 만들어줘.

[아이템] <이름> — <설명>
[규칙]
- 완전 투명 PNG, 정사각형
- 64x64 픽셀 아트 스타일
- 배경/테두리 없이 오브젝트만
- 어두운 배경 위에 올라가므로 밝고 채도 높게
```

현재는 이모지로 임시 대체하고 있다 (`src/config/items.ts` 의 `icon`).
아이콘 이미지를 넣을 준비가 되면 `iconKey` 로 바꾸면 된다.

## 5. 라이선스 기록 (대회 제출 필수)

AI로 생성한 에셋은 **④AI 활용 기술 문서**에 도구명과 생성 방식을 적어야 한다.
원본 시안은 `art-source/` 에 그대로 보관 중이므로 출처 추적이 가능하다.

- 캐릭터 시트: <생성 도구명> 으로 생성 → `tools/process-sheet.mjs` 로 전처리
- 사운드: 외부 음원 없음. Web Audio API 실시간 합성 (`src/systems/SoundSystem.ts`)
- 시트가 없는 캐릭터: Phaser 도형으로 코드 드로잉 (`src/characters/CharacterArt.ts`)
